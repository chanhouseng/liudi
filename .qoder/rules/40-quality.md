# 完成定义与交付格式

## DoD（八条全满足才算完成）
- [ ] 真机上点过（DevTools 模拟不算）
- [ ] 空 / 加载 / 失败 三态都有
- [ ] 断网行为符合 `PRD.md §7` 降级矩阵
- [ ] `npm run build` 通过，初始 JS < 250KB gzip
- [ ] 相关单测通过；改了规则引擎则覆盖率 100%
- [ ] 无新增第三方网络请求（Network 面板确认）
- [ ] 金额显示 `¥1,234`，等宽数字
- [ ] 涉及金额 / 判定的页面有免责声明

## 交付回复格式（缺"验收对照"视为未完成）
```
## 完成：T13 差异检测
**改了哪些文件**：lib/diff.ts, lib/diff.test.ts
**验收对照**：
- 纯函数、不碰 DOM ✅
- 5 组图 IoU > 0.6 ✅（0.71 / 0.68 / 0.83 / 0.77 / 0.65）
**没做的**：低对比度墙面偶发漏检，已记 TODO
**需要人确认的**：无
```

## 一次只做 1–2 张任务卡
不要"顺手"重构已完成模块，不要新增 PRD 里没有的页面或字段。
不要为了让测试通过而改测试预期（除非测试本身写错，且要在回复里说明原因）。

## 卡住就问，不要猜
需求歧义、缺数据、涉及法律表述、要引新依赖、要改数据结构 —— 停下来问。
提问格式：`【阻塞】任务号 / 现象 / 我的判断 / 需要你决定什么`。
